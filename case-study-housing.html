02 / Data quality

Better analysis starts with cleaner data.

Preparing inconsistent Nashville housing records for more reliable analysis with SQL Server.

Project type
Public portfolio project
Focus
Data preparation
Tools
SQL Server
Evidence
SQL script
01 / Question02 / Approach03 / Contribution04 / Outcome & evidence

The question.

How can inconsistent property records be standardised into a dataset that is easier to query and analyse?

The NashvilleHousing table contains parcel identifiers, property and owner addresses, sale dates and prices, and vacancy flags. The script addresses missing addresses, inconsistent categories, and duplicate records before downstream analysis.

The approach.

  • Convert sale dates to SQL DATE values in a dedicated column.
  • Fill missing property addresses using a self-join on ParcelID, then split property and owner addresses using string functions.
  • Normalise SoldAsVacant values from Y/N to Yes/No. Identify duplicate records with ROW_NUMBER in a common table expression, then remove duplicates and redundant columns.

The contribution.

The SQL script records the cleaning steps for the housing dataset. It makes the transformations inspectable rather than leaving preparation as an undocumented manual step.

What the work shows.

The deliverable is an inspectable SQL transformation workflow: consistent dates and categories, separately queryable address fields, and a defined duplicate-removal rule. The script is the evidence; row counts and error-reduction figures have not been independently reproduced for this case study.

This is a learning project. Production use would require backups, non-destructive transformations, data-quality assertions, and validation against the original records.
